# KG experiment — audit and results

Code: branch `fix/experiment-integrity`, experiment run at **`c3eb693`** with no modified
tracked files (`config.json`).

Commands:

```sh
PYTHONHASHSEED=0 sh scripts/run_experiment.sh outpath/experiments
.venv/bin/python scripts/collect_results.py outpath/experiments paper_artifacts
sh scripts/smoke_fold1.sh                                     # the fold-1 table in section 1
.venv/bin/python scripts/make_tables.py paper_artifacts      # regenerates every table below
```

Every table in this report is generated by `scripts/make_tables.py` from the pipeline's outputs
(`results_summary.csv`, `significance.csv`, `config.json`, `smoke/smoke_fold1.csv`). Numbers
quoted in the prose are copied from those generated tables. No value is taken from the thesis.

**Primary dataset: `readme_8k_desc20`.** It is the variant with the highest metrics, chosen by the
project owner after this experiment. The other two variants are reported for completeness.

## 1. What was broken, and what each fix changed

At the last commit before this work (`d0f7f9c`) the pipeline could not produce a hybrid result.
The fixes existed only as uncommitted edits from earlier sessions; they are now one commit
each. Effects were measured on **fold 1 (65 test projects, readme_8k_desc20 CNBN seeds)** by
reverting one fix at a time on top of the current code (`scripts/smoke_fold1.sh`):

- **Bridge delimiter (fix 1a).** CNBN wrote commas, TopFilter split on `;`: 0 of 644
  repositories got a seed, and the hybrid ran CF on an empty profile.
- **Seed prefix (fix 1b).** `#DEP# topic` never matches ground truth: SR@1…6 = 0.
- **Fold count (fix 2).** `runner.py` *and* `validator.py` each had an unconditional `break`,
  and CNBN overwrote its seed file every fold. Fold 1 is unaffected by construction; the effect
  is coverage: 1 fold / 65 projects before, 10 folds / 644 projects after.
- **Fold arithmetic (fix 3).** Validator `N // 10` against runner `ceil(N/10)`: fold 1 was
  scored on 64 of its 65 projects, fold k's window was shifted by k−1 projects, and projects
  641–644 were never scored.
- **KG cut-off (defect 4).** Not fixed, deliberately: making neighbours visible means changing
  the method or the cut-off. Measured in §3 instead.
- **Rank offset in the hybrid metrics.** Ranks 6–10 re-scored the five seeds, so P@10 was
  exactly P@5/2 and every curve was flat from N=5 to N=10.
- **Combined-graph seeding (found during this work, `c3eb693`).** The first training repository
  of every fold was copied into the combined graph with its local node IDs. Its topics were
  never interned, and its edges were credited to whichever topics later got global IDs 1…n
  (fold 1: AppFlowy's eight topics became out-links of `#DEP#javascript`). That skewed eight
  IDF counts per fold and made the output depend on the topic order inside `dicth_` files. The
  fix merges it like every other repository. Against the run before the fix, 106 of 2,700
  fold-level values changed and every conclusion is unchanged.
- **Checked and found to have no effect:**
  - Removing the `get_libraries` ground-truth re-read: it returns the same set for all 644
    projects. An earlier note claimed it inflated the results; it did not.
  - Regenerating `dicth_`/`graph_`/`projects.txt` with the committed preprocessing: same
    projects, same topic sets and graph files, and, after the combined-graph fix, identical
    results. Run end to end from `repo_readme/`, the whole pipeline
    (`scripts/run_corpus_pipeline.sh`) reproduces the primary experiment: 1,200 of 1,200
    result values identical.
  - `PYTHONHASHSEED` 0 against 12345: identical metrics. Similarity scores still differ in the
    last floating-point digit (set iteration order in `topic_similarity_calculator`), so every
    run pins `PYTHONHASHSEED=0`.

Other commits carried over from earlier sessions:
- a shared fold assignment and clearing of stale fold trees, which removed a train/test leak;
- a deterministic CF column order;
- a guard on the training-topic KeyError;
- single TF-IDF in CNBN by default. This **changes CNBN relative to the original code**, which
  applied IDF twice. It applies to every run equally.

## 2. Data and configuration

- **Repositories:** 644, from `repositories_test.csv` (1,000 mined repositories) after
  preprocessing.
  - Ten folds by stable hash of the name, seed 42: nine folds of 65 and one of 59.
  - CNBN and TopFilter use the identical test set in every fold, and zero train/test overlap
    was verified in every fold tree.
- **Dataset variants** differ only in the text CNBN trains on; TopFilter's data is the same for
  all three. Each corpus was rebuilt from `repo_readme/` and matched byte-for-byte (1000/1000
  files) with:

  | variant | `scripts/rebuild_readme_corpus.py --src repo_readme` flags |
  |---|---|
  | **readme_8k_desc20** (primary) | `--max-bytes 8192 --descriptions repo_descriptions.csv --description-repeat 20 --with-languages` |
  | readme_8k | `--max-bytes 8192` |
  | meta_only | `--no-readme --descriptions repo_descriptions.csv --description-repeat 1 --with-languages --with-name` |

- **Model settings:** τ = 5 CNBN-predicted topics per test repo (no real topics are shown), and
  k = 20 CF neighbours. N = 1…10 is reported; N = 1…20 is computed.
- **Ground truth:** the test repo's full normalised topic set. There is no topic split.
- **Success rate@N:** at least one correct topic in the top N.
- **Catalog coverage@N:** distinct topics in the top N across a fold's test projects, divided by
  distinct topics across that fold's training repositories.
- **Aggregation:** unweighted mean and sample standard deviation of the ten per-fold values.
- **Runs:**
  - A = KG off.
  - B = `KG_ENABLED=1 KG_MODE=append`.
  - C = `KG_ENABLED=1 KG_MODE=rerank` (λ 0.5, 10 sources).

  Within a variant all three runs share one CNBN seed file (CNBN is run with the KG off), so
  they differ only in the Topics Merger.

## 3. Does the knowledge graph change the metrics?

**Append (run B) has no measurable effect.** B equals A in every metric, at every N, in every
fold of every dataset. All 120 A-vs-B Wilcoxon tests are undefined because every paired
difference is exactly zero.

B did run with the KG on: recommendation lists grew from 80.5 to 296.4 entries on average
(readme_8k_desc20). But the neighbours are appended after the full CNBN+CF list, whose shortest
length is 51, so the top 20 is identical to A for all 644 projects. Worked example
`11ty/eleventy` (readme_8k_desc20, run B): 86 original topics, the first neighbour at rank 87
(`web-development`, a miss), and none of its neighbours is in the ground truth.

**Rerank (run C) makes the recommender worse.** Ranks 1–5 cannot change, because the hybrid
metrics pin them to the CNBN seeds.
- From N = 6 on, C is below A for success rate, precision and recall on all three datasets, at
  every N (45 of 45 cells).
- On the primary dataset at N = 10: success rate −0.0265 (p 0.0118), precision −0.0136
  (p 0.0050), recall −0.0185 (p 0.0020).
- Catalog coverage rises slightly at N = 6–8 on some datasets and falls at N = 10.

## 4. What I could not verify or run

- **Enlarged corpus.** The 10,000-repository selection is frozen (`enrich/top10k.rule.json`
  records its rule, counts and sha256; the CSV itself is data and is not committed). No README
  has been fetched yet: the token that was hard-coded in `preprocessing/miner.py` (now moved to
  the git-ignored `.env`) returns HTTP 401, so a new token is needed.
- **Definitions left unchanged.** Per the ground rules; each one affects A, B and C equally.
  - 41% of CNBN seed slots are raw labels absent from TopFilter's normalised vocabulary.
  - Catalog coverage: the `_b` version is overwritten by the plain one, and the numerator is not
    restricted to the catalog.
  - The CF "cosine" divides by √(‖a‖‖b‖).
  - The `stars ≥ 10` preprocessing filter actually reads the issue count.
- **Earlier reported values** (thesis, defence slides, `docs/METRICS.md`) are not used and were
  not reconciled. Every table here comes from running the pipeline.
- **Paper datasets D1–D3.** `dataset/topfilter/D1/` is empty and `Ten-fold_D0.rar` is not
  extracted, so none of the HybridRec datasets were run.
